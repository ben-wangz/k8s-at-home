# Security

## Authentication boundaries

| Boundary | Configuration | Purpose |
| --- | --- | --- |
| Client to backend | `backend.clientAuth` | Registry pull, push, delete, and catalog access. Disabled by default for trusted networks. |
| Operator to admin listener | `backend.adminAuth` | Task operations, Referrer reconciliation, GC, metrics, and API documentation. Always authenticated. |
| Backend to Distribution | `backend.distributionAuth`, `registry.auth`, `registry.tls` | Private Registry access over verified HTTPS. Generated by default. |
| Backend to upstream | Secret injected through `backend.extraEnvFrom` | Authority-specific upstream credentials, transport rules, and proxy configuration. |

Client credentials are never forwarded to Distribution or upstream registries. Admin credentials are separate from client credentials. The backend supports configured Basic credentials and static Bearer tokens; it does not register accounts or issue tokens.

With client authentication disabled, any caller that can reach the client listener can pull, push, and delete. Enable client authentication before granting access beyond your trusted network.

External HTTPS is terminated by Ingress or a reverse proxy. The chart's Ingress exposes only the client listener. Keep the admin Service private and restrict its access to operators and monitoring. Distribution is private, and its NetworkPolicy permits backend access.

## Generated admin credentials

The default admin Secret is `<fullname>-admin-auth`, with JSON stored under `config.json`. The generated account is `admin`, with `task-admin`, `referrer-prune`, and `gc-admin` permissions. The initialization Job persists an immutable Secret and an initialization record; restarts and upgrades reuse them.

For a default release name, prepare a temporary netrc file without printing the password. This example requires Bash, `kubectl`, and Python 3, and uses a directly reachable Service address:

```sh
set -euo pipefail
NAMESPACE=develop
RELEASE=registry-hub
FULLNAME="${RELEASE}-registry-hub"
ADMIN_HOST="${FULLNAME}-admin.${NAMESPACE}.svc"
ADMIN_URL="http://${ADMIN_HOST}:8081"
umask 077
ADMIN_NETRC="$(mktemp)"

kubectl -n "$NAMESPACE" get secret "${FULLNAME}-admin-auth" -o json |
  python3 -c '
import base64, json, sys
secret = json.load(sys.stdin)
auth = json.loads(base64.b64decode(secret["data"]["config.json"]))
credential = auth["basic"][0]
sys.stdout.write("machine {host} login {username} password {password}\n".format(
    host=sys.argv[1], **credential))
' "$ADMIN_HOST" > "$ADMIN_NETRC"

curl --fail --silent --show-error --netrc-file "$ADMIN_NETRC" \
  "$ADMIN_URL/openapi.yaml"
```

For a ClusterIP, set `ADMIN_HOST` to that IP before creating the file. With name overrides or an external admin Secret, use the actual fullname, Secret name, and key. Reuse `ADMIN_URL` and `ADMIN_NETRC` for the other guides, then remove the temporary file with `rm -- "$ADMIN_NETRC"`.

The authenticated `/docs` page provides Swagger UI. Its browser assets load from `unpkg.com`; `/openapi.yaml` and `/openapi.json` provide the API description directly.

## Client and admin credential files

Both domains accept the same JSON structure, with separate files and credentials:

```json
{
  "basic": [
    {
      "username": "reader",
      "password": "REPLACE_WITH_A_RANDOM_PASSWORD",
      "permissions": ["pull"]
    }
  ],
  "bearer": [
    {
      "token": "REPLACE_WITH_A_RANDOM_TOKEN",
      "permissions": ["pull"]
    }
  ]
}
```

Each credential must declare permissions. Use only the entries and permissions needed for its listener:

| Permission | Access |
| --- | --- |
| `pull` | Read Registry content, tags, and Referrers. |
| `catalog` | List local repositories when catalog is enabled. |
| `push` | Upload and publish Registry content. |
| `delete` | Delete local Registry content. |
| `task-admin` | Query and operate tasks, clean temporary state, and read metrics. |
| `referrer-prune` | Query and reconcile Referrers. |
| `gc-admin` | Query, trigger, retry, recover, and reconcile GC state. |

API documentation accepts any of the three admin permissions. Metrics require `task-admin`, which also grants task operations.

Create a Secret from a protected local credential file:

```sh
kubectl -n "$NAMESPACE" create secret generic registry-hub-client-auth \
  --from-file=config.json=/secure/path/client-auth.json
```

Select it with `backend.clientAuth.existingSecret` and `key`, as shown in the [client authentication configuration](../tests/features/client-auth-catalog/config.yaml). Admin credentials use `backend.adminAuth.existingSecret` and `key` instead. Invalid configured client credentials prevent startup; they do not fall back to anonymous access.

With `HUB` set to the client endpoint from [Usage](usage.md), choose the matching login command and enter your Basic username and password when prompted:

```sh
docker login "$HUB"
podman login "$HUB"
helm registry login "$HUB"
oras login "$HUB"
```

## Upstream and proxy configuration

The [upstream configuration](../tests/features/upstream-auth-transport/config.yaml) injects a Secret through `backend.extraEnvFrom`. Its environment keys contain JSON values:

| Secret key | JSON value |
| --- | --- |
| `REGISTRY_HUB_UPSTREAM_AUTH_CONFIG` | An authority map, such as `{"registry.example.com":{"type":"basic","username":"reader","password":"REPLACE_WITH_A_RANDOM_PASSWORD"}}`. Bearer entries use `type: "bearer"` and `token`. |
| `REGISTRY_HUB_UPSTREAM_TRANSPORT_CONFIG` | An authority map, such as `{"registry.example.com:5443":{"caFile":"/etc/registry-hub/upstream-tls/ca.crt","ports":[5443]}}`. Mount the matching CA file. HTTP requires explicit `allowHTTP: true`. |
| `REGISTRY_HUB_PROXY_CONFIG` | Proxy selection, such as `{"default":"http://proxy.example.com:8080","authorities":{}}`. Authority entries override the application default. |

Standard `HTTP_PROXY`, `HTTPS_PROXY`, and `NO_PROXY` variables can also be injected. Environment proxy selection takes precedence over application settings, and `NO_PROXY` permits matching targets to connect directly. A failed selected proxy does not cause a direct fallback.

Transport rules do not bypass SSRF checks. Private, loopback, link-local, metadata, and other reserved upstream targets are blocked, including redirect and token targets. Registry credentials remain bound to their configured authority.

## Storage credentials and lifecycle

Backend S3 credentials use `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY` in `storage.s3.credentialsSecret`. Distribution S3 uses the same keys in `registry.storage.s3.credentialsSecret`; the chart injects them into the Registry Pod and GC Job environment. Use a CA Secret containing `ca.crt` for endpoints with a private CA.

Generated internal material is stored in a separate Secret: backend auth JSON, bcrypt htpasswd, `ca.crt`, `tls.crt`, `tls.key`, and `http-secret`. Custom internal authentication must configure both `backend.distributionAuth.existingSecret` and `registry.auth.htpasswdSecret`, with matching credentials. Custom TLS uses `registry.tls.existingSecret` and its configured certificate, key, and CA keys. Custom HTTP secret uses `registry.httpSecret.existingSecret` and `key`.

Generated Secrets are immutable and are not automatically rotated or renewed. To change credentials or certificates, provide new external Secrets, update their chart references, and restart the affected workloads. Internal TLS certificates must cover the Distribution Service names and be trusted by the backend. Never delete initialization state as a rotation mechanism. Include all credential and initialization resources in [backups](operations.md#backup-and-restore).

## Resource limits

Default limits include 16 MiB per manifest, 256 MiB per upload request, 100 GiB per blob, and 10,000 objects or 1 TiB per root content closure. The closure size is the content budget for one artifact and its required references, independent of PVC capacity. Upload sessions expire after 30 minutes idle or 24 hours total lifetime.

Limits are read from `REGISTRY_HUB_LIMIT_*` and related environment variables defined in [config.go](../src/internal/config/config.go). Supply overrides through `backend.extraEnvFrom`; `backend.limits.referrerPages` has a dedicated chart setting. Size and request admission failures return Registry errors such as `413`, `429`, or `503`. Where supplied, honor `Retry-After`; raising a budget does not disable digest, structure, TLS, or SSRF validation.
